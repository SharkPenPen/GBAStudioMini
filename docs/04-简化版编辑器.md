# 04 · 简化版 GBA 编辑器方案

> **相关**：场景画布见 [08-场景画布方案.md](08-场景画布方案.md)。
> 图块无属性、8×8、逐帧判定、变量/UI/触发器是内容层、对象字段服务两类玩法。

> 2026-10-29。基于两件事：当前已迁移的编辑器源码（editor/app/main.cpp，6,307 行、166 个函数、8 个工具），
> 以及 GBA 的硬预算（240×160、4 层 BG、16 色、1792 个 BG 图块、1024 个 OBJ 图块、128 条 OAM）。

---

## 0. 结论

| 决定 | 内容 |
| --- | --- |
| 工具数 | **8 → 6**：资源 / 图块 / 对象 / 场景 / 过渡 / 设置 |
| 动画 | 不再是独立工具，并入「对象」的标签页 |
| 流程 | 独立工具只保留「场景过渡图」；对象行为流程并入对象 |
| 删除 | 插件、数据库两个空壳页；旧版的 Team / Spawner / 射击 / 组件 / 变量 / UI 文本 / 交互点 / 修饰器 |
| 新增 | 常驻 **GBA 预算条**；调色板 bank 面板；逐帧 OAM 预览；构建/运行按钮 |
| 数据 | 只暴露 v1 子集；未支持字段保留在 JSON 的 raw 里，旧工程不丢数据 |
| 代码 | 先删后拆：main.cpp 6.3k → 约 1.4k 壳 + 6 个页面 + 2 个 GBA 模块 |

**一句话：把「PGMMV 克隆」收成「GBA 平台动作关卡工作室」。**

---

## 1. v1 产品边界

**做**：横版平台动作；3 屏小关；1 个玩家；3 种敌人；金币 / 危险 / 终点；HUD；1 首 BGM。

**不做**：俯视 / RPG / 对话树 / 变量系统 / 通用 UI 文本 / 插件 / 数据库 / 旋转缩放 / 粒子 / 音频流。
这些不是「以后再说」，是 v1 明确不做；写在这里防止 UI 又被撑大。

## 2. 信息架构：8 → 6

当前 8 个工具：

~~~text
场景 | 图块 | 动画 | 对象 | 资源 | 流程 | 插件 | 数据库
~~~

改成 6 个：

~~~text
资源 | 图块 | 对象 | 场景 | 过渡 | 设置
~~~

| 现在 | 去哪 |
| --- | --- |
| 动画（工具 2） | 并入对象页：动画 / 流程 / 判定 三个标签 |
| 流程（工具 5） | 改成「过渡」：只画场景连接 + 出口条件，不做对象流程 |
| 插件（工具 6） | 删除（空壳） |
| 数据库（工具 7） | 删除（空壳） |
| 场景 / 图块 / 对象 / 资源 | 保留，按 GBA 预算裁剪 |

### 布局

~~~text
┌ 文件  编辑  构建  帮助 ─────────────────────────────── [构建 GBA] [运行] ┐
│ 资源 | 图块 | 对象 | 场景 | 过渡 | 设置                                │
├────────────┬────────────────────────────────┬──────────────────────────┤
│ 左：列表    │ 中：画布 / 时间线 / 流程图       │ 右：属性                 │
│            │                                │                          │
│            │                                │ （属性下方固定预算区）    │
├────────────┴────────────────────────────────┴──────────────────────────┤
│ BG 1200/1792 ▓▓▓▓░  OBJ 320/1024  PAL 5/16+4/16  OAM 12/128  ROM 96KB  │
└─────────────────────────────────────────────────────────────────────────┘
~~~

**预算条常驻底部**，不是藏在某个设置页里。超 80% 变黄，超 100% 变红，构建直接失败。

## 3. 六个工具各自做什么

### 3.1 资源

- 图像：导入 PNG、看原图、看量化后的 15 色预览、看它被哪些图块组/对象引用。
- 调色板：BG 16 组 + OBJ 16 组，每组 16 个色块；显示「谁在用这组」。
- 删除音频/变量标签（v1 不做）。

### 3.2 图块

- 左：图块组列表。
- 中：图块网格；8×8 / 16×16 切换；墙标记；gimmick（普通/金币/危险/终点）。
- 右：图像、列数、调色板 bank、硬件图块统计（去重后）、每类图块数量。
- 关键数字：**去重后的 8×8 图块数**，不是原图格子数。

### 3.3 对象

- 左：对象列表 + 新建（玩家/敌人/道具/子弹模板）。
- 中：三标签
  - **动画**：动作列表（idle/run/jump/fall/attack/hurt/die）、帧时间线、逐帧攻击/受击盒。
  - **流程**：默认动作 + 动作框 + 连线 + 条件 + 优先级（列表顺序即优先级）。
  - **判定**：碰撞盒、受击盒、攻击盒、帧原点/偏移/翻转。
- 右：基础（名字/类型/图像/帧尺寸/HP/分数）、物理（速度/跳跃/重力）、调色板 bank。
- 删除：Team、Channel、Spawner、射击间隔、子弹速度、组件、方向列表、行为/巡逻/俯冲、音效字段。

### 3.4 场景

- 左：层列表（背景/主层/前景/碰撞）+ 实例列表。
- 中：240×160 画布；图块笔刷、橡皮、碰撞笔刷；放对象、拖对象、起点、相机框。
- 右：场景属性（图块组/滚动率/BGM）、相机（跟随/固定）、受控对象、层→BG 映射。
- 删除：变量、UI 文本、交互点、修饰器、游戏类型、自由 2D、自动卷轴。

### 3.5 过渡

- 中：场景流程图（节点 + 箭头）。
- 右：连接列表；类型只留「出口 / 分数 / 开关」三种；出口绑定场景里的出口区域。
- 删除：对象流程（已并入对象）、群组空壳。

### 3.6 设置

- 工程：名字、初始场景、ROM 标题/code。
- 调色板总表：16+16 组的占用情况。
- 构建：目标、工具链路径、上次构建日志。
- 构建按钮本身放工具栏，设置页只放参数。

## 4. GBA 硬件 → 编辑器约束

| 硬件 | 编辑器里怎么体现 |
| --- | --- |
| 240×160 | 场景画布只画这个取景框；相机框可拖动 |
| 4 层 BG | 固定 3 视觉层 + 1 碰撞层；层→BG3/BG2/BG1 映射，不自由加层 |
| 16 色 / 组 | 每个图块组、每个对象绑定一个 bank；导入时量化到 15+透明 |
| BG 1792 块 | 图块页与预算条显示去重后的块数；按图块组归因 |
| OBJ 1024 块 | 对象页显示每个动作/帧占的块数；最坏帧 |
| OAM 128 条 | 对象页显示每帧拆成几个 OAM 部件；场景页显示同屏实例合计 |
| 96 KB VRAM | 预算条显示 BG 地图 + 图块 + OBJ 的总占用 |
| 32 MB ROM | 构建页显示 ROM 大小；不压缩，不做分 bank |
| 4 通道 PSG | v1 不做音频；G5 再开 |

### 新增的四块 UI

1. **预算条**（底部常驻）：BG 图块、OBJ 图块、调色板、OAM、ROM；点击展开归因。
2. **调色板面板**（资源/图块/对象共用）：32 组色板，点选分配；超 15 色标红。
3. **逐帧 OAM 预览**（对象页）：当前帧拆成 8×8/16×16 部件，显示数量与越界。
4. **构建面板**（设置/工具栏）：错误列表 + 构建 + 运行；错误必须指名「哪个图块组/哪个对象/超多少」。

## 5. 数据模型：保留 / 隐藏 / 删除

原则：**UI 只暴露 v1 子集；未支持字段留在 JSON 的 raw 里，保存时原样写回。**
这样旧工程不会因为「打开一次」丢数据；导出器只读支持的字段，遇到不支持的字段给警告。

| 结构 | 保留 | UI 隐藏（v1 不导出） |
| --- | --- | --- |
| ObjectDoc | 名字/类型/图像/帧尺寸/碰撞/受击/攻击/HP/分数/物理/动作/流程 | team、channel、spawner、射击、组件、方向列表、行为/巡逻/俯冲、音效 |
| SceneDoc | 3 层、碰撞层、实例、起点、相机（follow/fixed）、受控对象、过渡 | 变量、UI 文本、交互点、修饰器、free2d/auto_scroll、lives/scroll_speed |
| TilesetDoc | 图像、8/16 尺寸、列数、gimmick、墙 | require_variable（变量条件） |
| Project | 名字、初始场景、屏幕 240×160、tile_size | player_count、bottom 屏（保留字段，不用） |

> 第一版不删数据结构的字段，只删 UI 和导出；等 GBA 运行时稳定后，再决定是否真正移除。
> 这样风险最低，也不会把「简化」变成一次数据迁移。

## 6. 代码：先删后拆

当前 main.cpp 的问题：

- 6,307 行、166 个函数，单文件。
- 8 个工具里有 2 个空壳（插件/数据库）、2 个可合并（动画/流程）。
- 一批函数根本没被调用（编译警告里能看到）。
- 旧版字段和面板占了大量分支。

### 第 1 刀：删（约 -1,500 行）

| 删除 | 估计 |
| --- | ---: |
| 插件/数据库页（左中右） | ~200 |
| 独立动画工具外壳、独立流程页外壳 | ~250 |
| 对象页的 Spawner / 组件 / 方向 / 音效段 | ~300 |
| 场景页的变量 / UI 文本 / 交互点 / 修饰器段 | ~400 |
| 未调用函数（DrawPreview、DrawToolBar、DrawSettingsLeft 等） | ~350 |

### 第 2 刀：拆（不减少行数，但让后面每次改都便宜）

~~~text
editor/app/main.cpp          窗口 / D3D11 / ImGui / 主循环        ~700
editor/app/shell.cpp         菜单 / 工具栏 / 三栏 / 状态 / 预算条  ~500
editor/pages/resources.cpp   资源 + 调色板                        ~450
editor/pages/tiles.cpp       图块                                  ~550
editor/pages/objects.cpp     对象（动画/流程/判定）                ~1,300
editor/pages/scenes.cpp      场景（画布/层/实例/相机）             ~1,300
editor/pages/transitions.cpp 过渡图                                ~250
editor/pages/settings.cpp    工程/ROM/构建参数                     ~300
editor/gba/budget.cpp        预算计算与归因                        ~500
editor/gba/build.cpp         导出 + 调工具链 + 错误                 ~350
editor/ui/widgets.cpp        共用控件（色板/数字框/标签）           ~300
~~~

目标：总行数约 4.5k–5k，单文件不超过 1.3k；**先删后拆，每拆一页都编译 + smoke**。

## 7. 分阶段与验收

| 阶段 | 内容 | 验收 | 估时 |
| --- | --- | --- | --- |
| **P1 减法** | 8→6 工具；动画/流程并入对象；删插件/数据库/空壳；删未调用函数 | 编辑器能开、6 个工具、旧工程能打开；无旧版字段出现在 UI | 2 天 |
| **P2 预算** | 底部预算条（只读）；资源页调色板总表；图块页硬件图块统计 | 数字与手算一致；超限标红 | 3 天 |
| **P3 对象** | 对象三标签；逐帧判定；OAM 预览；调色板 bank | 建一个玩家 + 一个敌人 + 动作/流程，保存重开 | 4 天 |
| **P4 场景** | 240×160 画布；层→BG 映射；碰撞笔刷；实例/相机 | 画 3 屏关卡，预算不超 | 4 天 |
| **P5 构建** | 导出器 → devkitARM → ROM → mGBA；错误列表 | 工具栏一键出 ROM 并在 mGBA 里跑 | 4 天 |
| **P6 收口** | 拆分 main.cpp；删死代码；文档 | 单文件 <1.3k；总行数 <5k | 2 天 |

P1 是纯减法，风险最低；P5 是产品闭环，风险最高。

## 8. 需要拍板的四件事

| # | 选择 | 推荐 | 影响 |
| --- | --- | --- | --- |
| 1 | 对象模型：保留动作/流程，还是改成预设行为（走/飞/跳/射）？ | **保留动作/流程**，但提供模板 | 预设更小，但回到「加行为要改代码」；现有编辑器已经实现了动作/流程 |
| 2 | 图块粒度：8×8 直接画，还是 16×16 元图块？ | **8×8 硬件 + 16×16 显示** | 16×16 更接近美术习惯，8×8 更省 VRAM；两者都支持，默认 16 |
| 3 | 逐帧判定：保留还是只做对象级？ | **保留逐帧** | 平台动作的攻击/受击必须逐帧；现有数据模型已经支持 |
| 4 | HUD：固定模板还是不做？ | **固定 SCORE / LIVES / HP 模板** | 通用 UI 文本太重；固定模板够 demo 用 |

## 9. 不做什么（v1 冻结）

- 插件 / 数据库 / 脚本 / 变量表达式。
- 通用 UI 文本编辑器（只留固定 HUD 模板）。
- 自由 2D / 自动卷轴 / 射击玩法（对象流程可以做，但不做专用 UI）。
- 音频编辑（G5 再说）。
- 多语言、多窗口、停靠布局。
- 自动图块（autotile）——v1.1。
