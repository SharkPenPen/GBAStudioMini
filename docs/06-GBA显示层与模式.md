# 06 · GBA 显示层与模式：4 个文本槽，还是 3 个自由层？

> 2026-10-29。回答一个具体问题：GBA 的图层类型/数量，应该怎样落到编辑器里。
> 结论：**方向对（层要带类型、要受硬件约束），但「删到 3 层」不是最优解。
> v1 建议固定 Mode 0、4 个文本槽、4bpp；仿射层不进 v1。**

---

## 0. 先纠正两个数字

1. **文本层就是图块层**。GBA 没有「文本层」和「图块层」两种东西；
   文本 BG（text BG）就是 tilemap 层，地图项指向 8×8 图块。
   另一类是 affine BG（旋转/缩放），再一类是 bitmap 模式（没有 tilemap）。
2. **Mode 0 有 4 个文本层**，不是 3 个。旧版编辑器用 3 个视觉层；
   GBA 在 Mode 0 下反而多一个槽。真正的限制是：
   - 想要仿射层，就得换 Mode 1/2，文本层数量下降；
   - 每层都要吃地图 + 图块 + 调色板预算；
   - 仿射层是 8bpp/256 色，和 4bpp/16 色管线不兼容。

所以「GBA 支持不到那么多层」这句话，对**仿射层**成立，对**文本层**不成立。

---

## 1. 硬件事实

### 1.1 显示模式

| Mode | BG 组成 | 适合 |
| --- | --- | --- |
| 0 | 4 个文本 BG | **平台/图块关卡（推荐）** |
| 1 | 2 个文本 + 1 个仿射 | 需要旋转/缩放背景的特殊关卡 |
| 2 | 2 个仿射 | 特殊效果 |
| 3 | 1 个 16bpp bitmap（240×160） | 标题/整屏图片 |
| 4 | 1 个 8bpp bitmap（240×160，双页） | 标题/整屏图片 |
| 5 | 1 个 16bpp bitmap（160×128） | 特殊 |

图块编辑器只能活在 Mode 0/1/2；Mode 3/4/5 没有 tilemap，不适合关卡。

### 1.2 BG 类型

| 类型 | 色深 | 地图项 | 每 8×8 图块 | 调色板 | 翻转 | 变换 |
| --- | --- | --- | --- | --- | --- | --- |
| text 4bpp | 16 色 | 2B（tile 10b + flip 2b + pal 4b） | 32B | 16 组 × 16 色 | 有 | 无 |
| text 8bpp | 256 色 | 2B（调色板位无效） | 64B | 256 色 | 有 | 无 |
| affine | 256 色 | 1B（8 位 tile 索引） | 64B | 256 色 | 无 | 旋转/缩放 |

补充：

- 文本层 BG0/BG1 **固定 4bpp**；BG2/BG3 在文本模式下可选 8bpp。
- 仿射层**只能 8bpp**，地图项只有 8 位 tile 索引，没有 per-tile 调色板/翻转。
- 文本地图尺寸：32×32 / 64×32 / 32×64 / 64×64 图块。
- 仿射地图尺寸：16×16 / 32×32 / 64×64 / 128×128 图块。
- BG0–BG3 各自有 2 位优先级；OBJ 也有 2 位优先级；数字越小越靠前。
- BG 调色板 512B：文本层是 16 组 × 16 色；仿射层是 256 色。
  Mode 1 同时有文本和仿射时，两者共用这 512B，调色板规划会明显更紧。

### 1.3 VRAM 账

| 用途 | 4 个 32×32 地图 | 4 个 64×64 地图 |
| --- | --- | --- |
| 地图 | 4 × 2KB = 8KB | 4 × 8KB = 32KB |
| 图块（4bpp） | 56KB ≈ 1792 块 | 32KB = 1024 块 |
| 合计（BG 64KB） | 64KB | 64KB |
| OBJ | 另 32KB（1024 块 4bpp） | 同 |

**结论**：4 个 32×32 文本层只吃 8KB 地图，不是瓶颈；
真正的瓶颈是图块数、调色板组数、OBJ 图块/OAM。
把 4 层砍成 3 层只省 2KB 地图，却少一个层——不划算。

## 2. 对编辑器的建议

### 2.1 v1 固定 Mode 0

- 4 个文本槽，全部 4bpp，16 色/组。
- 不做仿射、不做 bitmap 模式。
- 理由：平台动作不需要旋转缩放；4bpp/16 色和 GBA 图块管线最契合；
  仿射会把 8bpp/256 色/无 per-tile 调色板的问题带进来，v1 不值得。

### 2.2 槽位与角色

不要把「3 个自由视觉层」做成可加可删的列表；改成**固定 4 行硬件槽位**：

| 槽 | 角色 | 类型 | 默认优先级 | 视差 | 说明 |
| --- | --- | --- | --- | --- | --- |
| BG0 | HUD | text 4bpp | 0 | 0 | 分数/生命/提示；也可空着 |
| BG1 | 前景 | text 4bpp | 1 | 0.8 | 树/柱子/遮挡 |
| BG2 | 主层 | text 4bpp | 2 | 1.0 | 关卡主体 |
| BG3 | 背景 | text 4bpp | 3 | 0.5 | 天空/远景 |

- 每行可以「启用/停用」；停用=空槽，不占地图/图块。
- 不做「新增第 5 层」——硬件没有。
- 角色名可以改，但槽位固定；这样预算、优先级、导出都能算死。

### 2.3 优先级，不是 foreground 布尔

旧数据里 foreground 是「在对象之后绘制」的布尔；
GBA 不是 painter's order，而是**优先级数字**：

- BG0–BG3 各 2 位优先级；OBJ 也有 2 位。
- 想让前景盖住角色：把 BG1 优先级设得比 OBJ 高（数字更小）。
- 想让 HUD 永远最上：BG0 优先级 0，OBJ 优先级 ≥1。
- 编辑器应该显示一个最终层序（BG0..3 + OBJ），而不是只给一个「前景」勾选。

### 2.4 仿射层以后怎么加

- 不是给现有层加一个「仿射」勾选；它是**另一种 BG 类型**：
  8bpp 图块、256 色、1 字节地图项、无翻转、带变换矩阵。
- 加它意味着：Mode 1（2 文本 + 1 仿射）或 Mode 2（2 仿射）、
  新的图块/调色板管线、新的导出路径。
- v1 不做；数据模型可以留 kind 字段，以后加 Mode 1 不用改存档结构。

---

## 3. 为什么不是「删到 3 层」

1. **4 个文本层是 Mode 0 的完整能力**，不用白不用；地图只多 2KB。
2. **HUD 需要一个层**。如果砍到 3 层，要么 HUD 用 OBJ（吃 OAM + 字模），
   要么 HUD 和前景抢层；都不如 BG0 干净。
3. **层数不是主要预算**。图块、调色板、OBJ 才是；4 个 32×32 地图很便宜。
4. **以后要加前景/背景时不用改架构**；空槽停用即可。

如果某个游戏确实只需要 3 层，停用 BG1 或 BG3 就行——这是数据开关，不是架构删减。

---

## 4. 数据模型改动（相对 05 的 3 层模型）

- ProjectSettings 增加 display_mode（v1 固定 0；预留 1/2）。
- SceneLayer 增加：
  - bg_slot：0–3；
  - kind：text / affine（v1 只用 text）；
  - priority：0–3；
  - parallax_x/y：替代现在的 scroll_x/y（语义不变，改名更清楚）；
  - enabled：空槽开关。
- 去掉 foreground 布尔（用 priority 表达）。
- SceneDoc.layers 固定 4 个（BG0–BG3），不再「3 个自由层」。
- 旧 3 层数据迁移：背景→BG3、主层→BG2、前景→BG1，BG0 空。

## 5. 待确认

1. HUD 用 BG0，还是用 OBJ？我建议 BG0（省 OAM/字模，层序稳定）。
2. OBJ 优先级按对象设，还是按帧设？v1 建议按对象设一个 0–3。
3. 背景要不要 8bpp 文本层（BG2/BG3 可选 256 色）？v1 建议全 4bpp，
   避免调色板和 per-tile bank 复杂度。
4. 以后要不要 Mode 1（2 文本 + 1 仿射）？如果要，先做 8bpp 图块管线，再谈 UI。
