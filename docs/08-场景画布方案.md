# 08 · 场景无限画布：设计评审与修改方案

> 2026-10-29。只评审「场景画布」这一块，不执行。
> 结论：**无限画布的方向是对的，不要退回固定场景边界。**
> 但当前实现有 3 类问题：导航/坐标、编辑正确性、性能与 GBA 预算。
> 建议分 4 步改，不重写画布。

---

## 0. 结论

| 项 | 判断 |
| --- | --- |
| 无限世界 + chunk | **保留**。关卡可以任意长，负坐标也能用，这是对的 |
| y 向上、原点/起点/相机框分离 | **保留**，但相机框语义要改 |
| 图块/碰撞/触发/实例分层 | **保留** |
| 当前画布状态管理 | **要修**：切场景不 fit、全局变量是死的 |
| 对象编辑 | **要修**：放置/拖动/删除没有 undo，选中框不是实际大小 |
| 导航 | **要加**：fit、回原点、回起点、小地图导航、坐标读数 |
| 性能 | **要改**：低倍率逐格查 map，按 chunk 裁剪 |
| GBA 预算 | **要接**：场景 chunk/图块/地图占用 |

---

## 1. 现状（代码事实）

### 1.1 画布

- 视口就是画布：世界坐标由 pan/zoom 直接映射；画到哪，chunk 就在哪生成。
- 世界 y 向上；原点 (0,0) 在屏幕左下角；矩形用「左下 + 宽高」。
- 底格 8×8；chunk 16×16 cells = 128px；负坐标合法；擦空后 chunk 自动删除。
- 缩放 0.4–3.0；滚轮以鼠标为中心；中键拖动平移。
- 初始 pan 让 240×160 的屏幕框居中；pan_init 是 static，只初始化一次。
- 网格线 + chunk 边界线；chunk 边界是存储边界，不是世界边界。
- 相机框画在原点 (0,0)，240×160；原点绿十字；起点橙色 START。
- 图块笔刷：左键画、右键擦、N×M 框选；y 向上贴图。
- 碰撞层：每格 4 个边（上/右/下/左），左键写笔头、右键清格。
- 触发层：右键拖新建矩形（8px 对齐），左键选中/拖动。
- 实例：20×20 绿框；点击选中、拖动移动；放置模式点击放置。
- 每笔一次 undo：图块/碰撞笔按下时 PushUndo，拖动中不重复。

### 1.2 状态（这块问题最多）

- 画布的 zoom/pan 是 DrawScenePageCenter 里的 **static 局部变量**；
  全局 g_scene_zoom / g_scene_pan 是死变量（只定义，没使用）。
- g_scene_fit_requested 在 SelectScene 里被设为 true，但**没有任何地方读它**。
- g_show_camera_frame、g_snap_objects、g_marquee_active、g_scene_copy_mode、
  g_scene_stamp_mode 都是死变量（只定义）。
- 切场景时 pan 不重置、不 fit；如果新场景在别处，画布可能看起来是空的。
- 小地图固定按 240×160 映射，只画这个范围里的触发器/实例/起点；
  世界无限时，超出首屏的内容看不见，也没有点击导航。

### 1.3 编辑正确性

- **对象放置没有 PushUndo**。
- **对象拖动没有 PushUndo**（拖动过程只 MarkDirty）。
- **触发器拖动没有 PushUndo**（只有右键新建时 Push）。
- 对象选中/拖动用固定的 20×20 框，不是对象的 frame/collision 尺寸；
  大对象选不中、拖不准。
- 对象删除在右栏按钮里，没有 Delete 快捷键，也没有 undo。
- 多选/复制/粘贴/复制场景的代码存在，但函数没接线（编译器警告里能看到），
  画布上也没有框选交互。

### 1.4 性能

- 画布按可见格遍历，每个格调用 SceneDoc::TileAt；
  TileAt 每次做 FloorDiv + chunk map 查找 + vector 索引。
- 按 1764×955 视口、0.4x 估算：世界约 4410×2387 px，即 551×298 格
  ≈ **16.4 万次 TileAt / 帧**。1x 时约 2.6 万次。
- 没有按 chunk 裁剪；没有缓存可见图块列表；低倍率下可能明显卡。

### 1.5 与 GBA 的关系

- 无限世界对作者友好，但 GBA 的地图/图块预算是有限的。
- 当前画布没有显示「这个场景有多少 chunk、多少图块、地图占多少 VRAM」。
- 3 个视觉层还是旧版模型的；GBA 是 4 个文本槽 + 优先级（见 06），
  这一步要等数据模型改，不建议在画布里硬塞。

---

## 2. 保留什么

1. **无限世界 + chunk**：不要改成固定宽高的场景；长关卡、负坐标是真实需求。
2. **y 向上**：符合关卡设计直觉；翻转只在导出时一次。
3. **原点、起点、相机框三个概念分开**：现在的问题是相机框语义，不是概念本身。
4. **图块 / 碰撞 / 触发 / 实例四层**：不要合并；碰撞独立是这套设计的核心资产。
5. **每笔一次 undo**：粒度对；只是对象编辑没接上。
6. **chunk 边界显示**：帮助理解存储；但 16 cells = 128px，和 docs 里的 32 不一致，
   文档要改成 16。

## 3. 问题清单（按优先级）

### P0 正确性

1. 对象放置/拖动/删除、触发器拖动没有 undo。
2. 切场景不 fit；g_scene_fit_requested 是死变量；可能切到空白画布。
3. 相机框固定在原点，不是起点/相机位置；大关卡容易误读。
4. 小地图只看 0..240 / 0..160，无限世界下没用。

### P1 可用性

5. 没有 fit-to-content、回原点、回起点；没有坐标读数/标尺。
6. 没有笔刷 ghost；看不到落笔会画到哪。
7. 实例只有 20×20 框，不是实际 frame/collision；没有吸附；没有实例列表；
   多选/复制粘贴没接线。
8. 碰撞笔没有 bit4 单向平台；数据有、运行时也不读——要么做，要么删。
9. 中键平移对笔记本不友好；没有空格拖拽/边缘滚动。

### P2 性能 / GBA

10. 低倍率逐格 TileAt；应按 chunk 裁剪、直接拿 chunk 指针。
11. 没有场景 chunk/图块/地图预算提示。
12. 3 层 vs GBA 4 槽还没接；等数据模型改，不在画布里硬改。

## 4. 修改方案（建议顺序）

### S0 · 先定三件事（0.5 天，不写代码）

1. **场景大小策略**：
   - 推荐：**无限 + 软预算**。不设硬边界；预算条显示 chunk 数、图块数、地图字节；
     超过阈值警告，但不阻止。
   - 备选：每场景硬上限（如 512×512），简单，但回到固定关卡。
2. **相机框语义**：
   - 推荐：默认**跟起点**（显示首屏），可切换到「原点」或「拖动预览」；
     不写进工程数据。
   - 备选：固定原点（现状），大关卡会误导。
3. **单向平台 bit4**：
   - 推荐：v1 先不做；把数据/UI 里的 bit4 占位标成未实现，等运行时支持再加。
   - 备选：现在补画笔 + 运行时，成本更高。

### S1 · 导航与状态（1–2 天）

- 每个场景保存自己的 pan/zoom（编辑器状态，不写工程）；第一次打开自动 fit。
- 删除死变量，或把它们真正接上：
  g_scene_fit_requested、g_show_camera_frame、g_snap_objects。
- 快捷键/按钮：
  - F：fit 内容（用 ContentBounds + 边距）
  - Home：回原点
  - Shift+Home：回起点
  - 空格+拖动 / 中键：平移
  - 滚轮：以鼠标为中心缩放；范围放宽到 0.1–4.0
- 小地图：
  - 按 ContentBounds（含负坐标）映射，不再固定 240×160；
  - 画当前视口矩形；
  - 点击/拖动小地图跳转。
- 状态栏/画布角：显示世界坐标、格坐标、缩放、当前层。
- 相机框：默认跟起点；可切换「原点/起点/拖动预览」。

### S2 · 编辑正确性（2–3 天）

- 对象放置、拖动开始、删除、触发器拖动：都 PushUndo。
- 笔刷 ghost：鼠标下画 N×M 半透明预览。
- 对象选中/拖动用实际 frame 或 collision 框，不再固定 20×20。
- 吸附开关：8px 网格（g_snap_objects 已有变量）。
- 实例列表：左栏或右栏加一个列表（名称/对象/坐标），选中即定位；
  删除键可用。
- 矩形填充（图块/碰撞）如果 v1 需要，再加；否则先 ghost + 单格。
- 多选/复制粘贴：代码已有但没接线；决定「接上」还是「删掉」，不要留半套。

### S3 · 性能（1 天）

- 画布改为按可见 chunk 遍历：先算可见 chunk 范围，再直接访问 chunk.cells；
  不再每格 TileAt。
- 跳过空 chunk；低倍率时限制最大可见格数或降低网格绘制。
- 用一个大场景（如 64×64 chunk）在 0.4x 下测帧时间，目标 <8ms/帧。

### S4 · GBA 预算（1–2 天，G1 之后）

- 预算条增加：当前场景 chunk 数、唯一图块数、地图字节、OBJ 占用量。
- 如果运行时用 32×32 窗口流式，画布上标出「流式窗口」范围。
- 4 BG 槽（BG0–BG3）等数据模型迁移时一起改；不在画布里先画 4 层假数据。

## 6. 验收（改完后）

1. 打开任意场景，画布自动 fit；切场景不迷路。
2. 图块、碰撞、触发、实例的增删改都能 undo。
3. 0.4x 下 64×64 chunk 的大场景，画布帧时间 <8ms。
4. 小地图能反映内容范围和当前视口，点击能跳转。
5. 状态栏能读出鼠标处的世界坐标/格坐标。
6. 相机框默认在起点，能切换；不再和原点混淆。
