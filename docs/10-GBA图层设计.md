# 10 · GBA 图层设计与 512 地图上限

> 2026-10-31。已拍板：BG0 = HUD；地图最大 512×512 px；不做自动拆分。

---

## 0. 锁定的决定

| 项 | 决定 |
| --- | --- |
| 显示模式 | Mode 0，4 个文本 BG，全部 4bpp |
| BG0 | HUD / 固定 UI，32×32，不滚动 |
| BG1 | 前景，和主层同地图尺寸 |
| BG2 | 主层（关卡主体） |
| BG3 | 背景（天空/远景） |
| 地图上限 | 512×512 px = 64×64 格；新场景默认 64×32 |
| 场景 | 单场景最大 512×512；不做自动拆分、不做流式地图 |
| 调色板 | BG 16 组 × 16 色；bank 归 tileset |
| 仿射/8bpp | v1 不做 |

---

## 1. 槽位与优先级

| 槽 | 角色 | 地图 | 滚动 | 默认 priority |
| --- | --- | --- | --- | --- |
| BG0 | HUD | 32×32 | 0 | 0（最前） |
| BG1 | 前景 | 同主层 | parallax 100% 或更快 | 1 |
| BG2 | 主层 | 同主层 | 100% | 2 |
| BG3 | 背景 | 同主层 | 50% 左右 | 3 |
| OBJ | 玩家/敌人 | — | 跟随相机 | 2 |

- 数值越小越靠前。
- 玩家 OBJ priority = 2，和主层同优先级；GBA 同优先级时 OBJ 在 BG 前面。
- 前景 priority = 1，压住玩家；HUD = 0，压住所有。
- 待实测：同优先级 OBJ/BG 的先后。若 OBJ 反而在后，就把 OBJ 改 1、前景改 0。

## 2. 数据模型

### 2.1 SceneLayer 固定 4 个

    SceneLayer {
      bg_slot      0..3        // 固定，不可增删/排序
      enabled      bool        // 空槽
      visible      bool
      locked       bool
      priority     0..3
      parallax_x   int %       // 替代 scroll_x
      parallax_y   int %
      tileset      旧字段兼容
      chunks
    }

- 删除 foreground 布尔。
- layers 固定 4 个；EnsureLayers() 按 bg_slot 补齐。
- 场景增加 map_w / map_h，取值 32 或 64；BG1–BG3 共用。
- 碰撞仍是独立单层，不跟视觉层绑定。

### 2.2 旧工程迁移

    旧 背景   → BG3
    旧 主层   → BG2
    旧 前景   → BG1
    BG0       → 空 / HUD
    旧 foreground=true  → priority 1
    旧 scroll_x/y       → parallax_x/y

保存后写新 4 层结构；旧字段不再写。

## 3. 编辑器

保持三栏和画布操作，只改层相关：

- 画布上方 3 个层 tab → 4 个固定 tab：
  BG0 HUD / BG1 前景 / BG2 主层 / BG3 背景
- 不做「+ 层」和「删除层」；只做启用/显示/锁定。
- 右栏选中层：
  - 显示名
  - 启用
  - priority 0–3
  - parallax X/Y
  - 场景地图尺寸（64×32 / 64×64）
  - 图块/调色板预算
- 场景树「图层 (4)」固定 4 行。
- 删除 foreground 勾选，避免和 priority 二义。

---

## 4. 导出与运行时

### 4.1 地图

- BG1–BG3 各一张地图，同尺寸。
- BG0 可选，32×32，固定。
- 所有层共用一套 8×8 图块 bank（按图块去重）。
- 地图项 = tile index + palette bank；y 方向翻转一次。

### 4.2 滚动

    BGxHOFS = camera_x * parallax_x / 100
    BGxVOFS = camera_y * parallax_y / 100
    BG0     = 0

地图按 32/64 格回绕。

### 4.3 调色板

- 4bpp 文本层：BG 16 组 × 16 色。
- palette bank 归 tileset，不归层：
  - 一个 tileset 一个 bank；
  - 地图项写 bank << 12；
  - 超过 16 个 tileset/bank 报错，不静默。
- OBJ 独立 16 组；玩家占 bank 0。

---

## 5. 地图上限与拆分

- 单场景最大 64×64 格 = 512×512 px。
- 新场景默认 64×32（512×256）；可改 64×64。
- 超出地图的内容：导出时明确报错，不静默裁剪。
- 不提供自动 512px 拆分；场景由作者自己控制在 64×64 格以内。
- v1 不做流式地图。

---

## 6. 预算

| 方案 | 地图 | 图块余量 |
| --- | --- | --- |
| 3 层 64×32 + HUD 32×32 | 14KB | 50KB ≈ 1600 块 |
| 3 层 64×64 + HUD 32×32 | 26KB | 38KB ≈ 1216 块 |
| 4 层全 64×64 | 32KB | 32KB = 1024 块 |

底部预算条按这个口径显示；超了标红，导出报错。

---

## 7. 不采用

- 只做 3 层：省 2KB 地图，少一个硬件槽。
- 4 层自由增删：硬件固定 4 个，自由列表只会制造「第 5 层导出失败」。
- BG2/3 用 8bpp：64B/图块、无 per-tile 调色板、图块数减半。
- 仿射层：v1 不需要，会把 8bpp/256 色/无翻转带进来。
- 每层一套调色板：同一 tileset 复用时会被迫复制。

---

## 8. 实施顺序

1. U2a：数据模型固定 4 层 + 旧 3 层迁移。
2. U2b：编辑器 4 个固定 tab + 层属性。
3. U2c：导出器多地图 + 共享图块 + palette bank。
4. U2d：运行时 BG0–3 初始化、优先级、滚动、视差。
5. U2e：预算条按 4 层口径精确化。

验收：

- 旧工程打开后背景/主层/前景落在 BG3/2/1，BG0 空。
- demo 能看到天空、平台、前景；玩家夹在前景和主层之间。
- 没有第 5 层；地图超过 64×64 明确报错。
- 3 层 64×32 时地图+图块在 64KB 内，调色板不超过 16 组。
