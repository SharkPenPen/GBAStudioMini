# 12 · 触发器与规则（v1 设计）

> 2026-11-05。区域、规则、条件、动作、界面的 v1 字段表。
> 目标：把“触发器”从“自带动作的对象”拆成“区域数据 + 规则 + 动作”，让引擎不认识“胜利/失败/平台/解谜”。

## 0. 范围

- 区域：矩形，场景内唯一命名。
- 规则：条件（全部满足）+ 动作（按顺序）。
- 动作：显示/隐藏界面、播音、设变量、切场景、生成、销毁、等待。
- 界面：模态/非模态、淡入淡出、按确认/定时关闭。
- 不做：格子/多边形区域、区域组、“或者”条件、计数条件、对象属性变量、独立计时器、动作取消、规则状态存档、界面元素动画、菜单导航。

## 1. 三条总规则

1. **区域只描述“哪块地方”**，不带任何行为。
2. **规则 = 条件（全部满足）+ 动作（按顺序）**。
3. **动作可以等，界面可以暂停/锁输入**。

## 2. 区域（Zone）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 字符串 | 场景内唯一，规则用它引用 |
| name | 字符串 | 显示名 |
| x, y, w, h | 整数 | 场景坐标，像素 |
| enabled | 布尔 | 关掉就不参与判定 |

- 坐标与场景对象、触发器一致；场景数据的 y 翻转只在加载时做一次。
- 多个区域可以重叠；规则按名字引用，不按顺序。
- v1 只有矩形；数据里留 shape 字段，以后加格子/多边形。

## 3. 规则（Rule）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 字符串 | 唯一 |
| name | 字符串 | 显示名 |
| enabled | 布尔 | 开关 |
| trigger | 四选一 | 每帧 / 进入 / 停留 / 离开 |
| interval | 整数 | “停留”时每 N 帧查一次，默认 1 |
| once | 布尔 | 触发一次后自动关闭 |
| cooldown | 整数 | 触发后等 N 帧才能再触发，0 = 不等 |
| conditions | 列表 | 全部满足才触发（v1 只做“并且”） |
| actions | 列表 | 按顺序执行 |

触发方式：

- **每帧**：条件为真就执行（受 once/cooldown 限制）。
- **进入**：整组条件从假变真时执行一次。
- **停留**：条件为真时，每 interval 帧执行一次。
- **离开**：整组条件从真变假时执行一次。

规则不区分“触发器”和“对象规则”：区域只是条件的一种，规则本身是通用的。

## 4. 条件（Condition）

v1 只做这四类：

| 类型 | 参数 | 说明 |
|---|---|---|
| 区域包含 | 区域 id、对谁 | 对象在区域里 |
| 变量比较 | 范围、名字、比较符、值 | 例如 hp < 3 |
| 按键 | 键、状态 | 按下 / 按住 / 松开 |
| 总是 | 无 | 用于纯定时/纯动作的规则 |

“对谁”：

| 选项 | 说明 | v1 |
|---|---|---|
| 玩家 | 当前操控的对象 | 是 |
| 任何某类 | 场景里任意一个 type=X 的对象 | 是 |
| 所有某类 | 场景里所有 type=X 的对象 | v1.1（要计数） |
| 指定对象 | 按场景对象 id | 以后 |

“变量比较”的范围：全局 / 场景 / 对象属性（对象属性以后）。
比较符：== != < <= > >=。
v1 的变量是整数；浮点以后再说。

条件列表是“并且”：全部为真才触发。v1 不做“或者”和嵌套。

## 5. 动作（Action）

v1 动作：

| 类型 | 参数 | 说明 |
|---|---|---|
| 显示界面 | 界面 id | 见 §6 |
| 隐藏界面 | 界面 id | |
| 播音效 | 音效 id | |
| 设变量 | 范围、名字、运算、值 | 设 / 加 / 减 |
| 切场景 | 场景 id | |
| 生成 | 对象或类型、x、y | |
| 销毁 | 对谁 | |
| 等待 | 帧数 | 只用于动作之间 |
| 存档 | 槽位 | v1 固定 save0 |
| 读档 | 槽位 | v1 固定 save0 |

- 动作按列表顺序执行。
- “显示界面”执行后，动作列表**等界面关闭**再继续（这样“显示胜利 → 等确认 → 切场景”就是三条动作）。
- 界面 dismiss = 不关时，不等待，继续执行。
- 动作失败（变量不存在、场景不存在）记日志并跳过，不崩、不静默。

## 6. 界面（UiScreen）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 字符串 | 唯一 |
| name | 字符串 | 显示名 |
| elements | 列表 | 界面里的元素 |
| modal | 布尔 | 真 = 暂停游戏 + 锁输入 |
| transition | 二选一 | 无 / 淡入淡出 |
| fade_frames | 整数 | 淡入淡出多少帧 |
| dismiss | 三选一 | 按确认 / 定时 / 不关 |
| dismiss_frames | 整数 | 定时关闭的帧数 |

执行“显示界面”时：

1. 界面开始淡入（transition + fade_frames）。
2. 如果 modal：游戏暂停、输入交给界面。
3. 动作列表等界面关闭（dismiss 不为“不关”时）。
4. 关闭后继续下一条动作。

界面元素本身的设计见 GUI 文档；本篇只定“界面作为动作目标”的字段。

## 7. 执行顺序

- 每帧按规则列表顺序检查。
- 条件全部满足才触发。
- 一条规则的动作没跑完时又满足条件：**忽略**（v1）。
- 切场景在帧末执行；旧场景里没跑完的动作丢弃。
- 销毁在帧末执行，避免动作跑到一半对象没了。
- 多个规则可以在同一帧触发，各自跑自己的动作序列。
- 进入/离开的边沿检测按“整组条件”的真假，不按单个条件。

## 8. 组合示例

### 8.1 交互提示（走到门前显示提示，按确认对话）

- 规则 A：进入 + 区域包含（门，玩家）→ 显示界面 prompt
- 规则 B：离开 + 区域包含（门，玩家）→ 隐藏界面 prompt
- 规则 C：停留 + 区域包含（门，玩家）+ 按键（确认，按下）→ 显示界面 dialogue

三条规则组合，不需要“触发器”对象，也不需要“非”条件。

### 8.2 推箱子过关（单个箱子）

- 区域 goal_1，画在目标点上。
- 规则 A：进入 + 区域包含（goal_1，任何箱子）→ 播音效 + 设 done_1 = 1。
- 规则 B：每帧 + 变量比较（done_1 == 1）→ 显示界面 level_clear（modal，淡入 30 帧，按确认关闭）+ 切场景 next。

“所有箱子都进”是计数条件，v1.1 再做。

## 9. 旧数据迁移

| 旧的 | 新的 |
|---|---|
| Trigger 的 x/y/w/h | 区域 |
| Trigger.once | 规则的 once |
| require_variable / value | 变量比较条件 |
| actions | 规则（进入）+ 动作 |
| exit_actions | 规则（离开）+ 动作 |
| inside_actions / interval | 规则（停留）+ interval |
| win / lose | 显示界面 + 设变量 |
| change_scene | 切场景 |
| attr_add / set_variable | 设变量 |
| spawn / play_sfx | 生成 / 播音效 |
| interaction（按键提示） | 三条规则组合，见 §8.1 |
| 旧 UiText | 新界面元素：绝对 x/y → 左上锚点 + 偏移；scale → 最近字号；bar → 数值→条 |

旧动作 win/lose/change_scene 标记为“旧动作”，迁移后映射到新动作；不直接删字段，避免旧工程打不开。

## 10. 编辑器

- **区域层**：画/选/改矩形、命名、显示隐藏。
- **规则面板**：列表 + 触发方式 + 条件列表 + 动作列表。
- 条件和动作用**通用参数面板**：选类型 → 显示该类型参数；不要每个类型写死布局。
- **调试**：运行时高亮正在触发的规则/区域，能步进。
- **校验**：区域名唯一、引用的区域/界面/变量存在、动作参数合法。

## 10.1 已实现（p3d v81）

- 区域仍存在 scene.triggers 里；编辑器“触发器”页就是区域。
- 每条区域新增 rules：
  - enabled；
  - mode：进入 / 离开 / 在里面；
  - require_variable + require_value（空变量 = 总是）；
  - actions：复用现有动作。
- 运行时会先跑规则，再跑旧的进入/离开/停留动作；旧动作仍保留，等下一步迁移。
- 编辑器区域面板加了“区域规则”列表、动作列表、条件变量。

## 11. v1 不做

- “或者”条件、嵌套条件。
- “所有某类”的计数条件。
- 指定某个对象。
- 对象属性作为变量来源。
- 独立计时器。
- 动作取消/打断。
- 规则状态的存档。
- 格子/多边形区域、区域组。
- 界面元素的逐字/滑动动画。
- 菜单的按键导航（界面自己的事，不走规则）。

## 12. 待定

- 区域是否要“组”（多个区域算一个逻辑目标）。
- 计数的语义：所有都在、至少一个、正好 N 个。
- 动作序列的并发上限。
- 规则优先级：列表顺序够不够。
- 界面关闭后是否恢复游戏输入（默认恢复）。
